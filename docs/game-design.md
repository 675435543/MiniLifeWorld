## 0. 文档目的

本文档是 Mini Life World 的**唯一设计基线**。后续每个开发里程碑（M0~M7）都以本文档为验收依据；
实现过程中发现设计需要调整时，先改本文档，再改代码。

核心要求只有一句：**孩子拿到手机，打开就能玩，并且每一步都是真的。**
不允许用"漂亮的空壳"代替可玩功能。

## 1. 项目概述

### 1.1 一句话定位

面向儿童的**开放式「虚拟玩具屋 + 自由角色扮演」游戏**：没有关卡、没有失败、没有倒计时，
孩子在城市地图里选择建筑进入生活场景，拖动角色和道具，自由编自己的故事。

### 1.2 目标用户

- 主要：3–8 岁儿童（以及陪玩的家长）
- 特征：不识字或识字少、手指点按为主、注意力短、喜欢**即点即玩**、喜欢模仿日常生活
- 结论：交互必须是"看一眼就会"，反馈必须夸张且即时。

### 1.3 它是 / 它不是

| 是 | 不是 |
| --- | --- |
| 自由探索与角色扮演 | 闯关、收集、刷分 |
| 虚拟玩具屋（人物+道具可自由摆放组合） | 剧情线性手游 |
| 安全、温暖、无暴力的生活模拟 | 战斗、恐怖、竞技、社交 |
| 可长期扩展的框架 | 一次性小游戏 |

### 1.4 暂定产品名

Mini Life World / 我的小世界（正式品牌名后续再定，代码与资源内统一使用 `MiniLifeWorld`）。

## 2. 设计原则（所有实现决策的裁判）

1. **儿童优先**：按钮大（触摸热区 ≥ 48dp / 96px）、反馈明显、少文字多图形。
2. **零压力**：无失败、无倒计时、无惩罚、无强制任务。
3. **触摸原生**：所有交互按触摸设计（`InputEventScreenTouch / ScreenDrag`），鼠标只是兼容手段。
4. **自由创造**：角色与道具都能拖、能组合、能产生"像过家家"的效果。
5. **数据驱动**：角色、道具、场景、交互规则都来自配置（JSON/Resource），新增内容不改代码。
6. **真实可玩**：每个里程碑交付必须"能运行、能操作、验收清单全绿"。
7. **横屏单人**：横屏、单指操作、离线、无内购、无广告。

---

## 3. 核心体验循环

```
打开游戏 → 城市地图（点击建筑）→ 进入场景
   → 从角色栏拖出角色 → 拖动角色/道具 → 触发过家家式互动
   → 切换房间/场景 → 收集自己的"故事" → 返回地图 → 再来一遍
```

体验目标：**孩子不需要教，第一分钟就能自己玩起来。**

## 4. 技术选型

| 项 | 选型 | 理由 |
| --- | --- | --- |
| 引擎 | Godot 4.x Stable（4.4+） | 免费开源、2D 强、触摸支持好、可导出 Android APK |
| 脚本 | GDScript（静态类型） | 与引擎深度集成，AI 友好，迭代快 |
| 渲染 | 2D（CanvasItem 体系） | 玩具屋风格不需要 3D；2D 成本低、性能稳 |
| 基准分辨率 | 1920×1080，`canvas_items` 拉伸 + `expand` | 横屏手机主流分辨率，适配不同比例 |
| 屏幕方向 | 横屏（SensorLandscape 或 Landscape） | 场景宽、角色栏/道具栏横排 |
| 触摸 | `InputEventScreenTouch / InputEventScreenDrag` + 鼠标兼容 | 必须真机可玩 |
| 存档 | JSON 写入 `user://` | 简单可视、易调试、真机可用 |
| 导出 | Android APK（`minSdk 24`，Target 最新） | 直接安装到手机 |
| 版本管理 | Git + GitHub（已建仓库） | 每里程碑一个 commit，可回滚 |

> 不使用 3D、物理引擎、联机、账号系统、支付。第一版全部不需要。

## 5. 美术与资源策略

### 5.1 风格定位

- **玩具屋 / 过家家**风格：圆润、明快、暖色、轻度 2.5D（俯视偏侧，卡通比例）。
- 统一色板（初稿）：奶油底 `#FFF8EC`、暖橙 `#FFB74D`、珊瑚 `#FF8A65`、薄荷 `#80CBC4`、
  天蓝 `#64B5F6`、草绿 `#AED581`、描边深棕 `#5D4037`。
- 角色：大头小身、粗描边、简单五官；衣物可换色（MVP 用配色方案切换，后续可换装）。
- 所有素材**原创或由程序生成**，不得使用任何商业游戏素材。

### 5.2 资源策略（重要）

当前环境没有在线图片生成能力，因此 MVP 采用**程序化占位素材**：

- 角色/道具/背景用 Godot`_draw()` 或代码生成的 SVG/PNG 绘制（统一色板、圆角、描边），
- 在 `assets/` 下用目录约定区分 `placeholder/` 与将来正式素材；
- 所有资源路径写入数据配置（`sprite_path`），**替换素材不需要改代码**；
- 占位素材必须"看得出是什么、能产生正确交互反馈"，但允许朴素。
- 每个占位素材在文件名或 `README` 中标注 `placeholder`，里程碑 UI 不展示"占位"字样给儿童。

验收标准：占位美术也必须是**完整、可爱、统一**的，不出现裸色块拼贴。

### 5.3 美术资产规范（后续升级时）

角色比例 1 : 1.6（头身）、描边 8px@1080p、统一阴影（右下 45°、透明度 20%）、
图标 96×96、背景 1920×1080 可平铺或全幅。所有新素材需对照本文档第 5.1 色板。

## 6. 系统设计

### 6.1 场景与地图系统

**世界地图（WorldMap）**：一张城市全景图，含可点击建筑：

| 建筑 | 对应场景 | MVP 范围 |
| --- | --- | --- |
| 家 | Home | ✅ 完整可玩 |
| 医院 | Hospital | ✅ 完整可玩 |
| 学校 | School | ✅ 完整可玩 |
| 超市/餐厅/警察局/游乐场… | — | 预留入口（灰色/锁），后续版本解锁 |

- 建筑热区用 `Area2D` + 输入处理，点击后播放"建筑放大 → 淡入场景"过渡。
- 地图底部显示已解锁场景图标，便于孩子快速返回常用场景。

**场景（SceneBase）**：每个场景一个 `.tscn`，统一继承 `SceneBase`：

```
SceneBase (Node2D)
├── Background (Sprite2D/Node2D)
├── Props (Node2D)          # 道具容器，挂 Item 节点
├── Characters (Node2D)     # 角色容器
├── Zones (Node2D)          # 交互区域（床、椅子、沙发等热区）
└── UI (CanvasLayer)        # 返回按钮、角色栏、道具栏、提示
```

- `SceneManager`（Autoload）：`enter_scene(scene_id)` / `back_to_map()`，负责淡入淡出、
  存档场景切换、跨场景共享角色池。
- 场景内角色与道具位置**按场景分别保存**（同一角色在不同场景有各自位置，符合过家家直觉）。

### 6.2 角色系统

**角色数据**（`data/characters.json`）：

```json
{
  "id": "mom",
  "name": "妈妈",
  "palette": {"skin": "#FFCC9C", "hair": "#5D4037", "shirt": "#FF8A65", "pants": "#64B5F6"},
  "outfits": [{"id": "home", "shirt": "#FF8A65"}, {"id": "work", "shirt": "#80CBC4"}],
  "unlock": 0
}
```

- MVP 角色（6 个，男女老幼都有，覆盖三个场景）：妈妈、爸爸、宝宝（幼儿）、哥哥、姐姐、医生（可兼护士配色）。
- `Character.tscn`：`Node2D` + 程序绘制躯体（后续可换 `AnimatedSprite2D`）+ `Area2D` 拾取热区 + 状态机。
- 状态机（MVP 用简单枚举 + 动画混合，不做复杂行为树）：

| 状态 | 表现（MVP 程序动画） |
| --- | --- |
| idle | 轻微呼吸缩放（1.0 ↔ 1.02） |
| walk | 左右摆动 + 上下浮动 |
| sit | 下移躯干、腿收起，Z 排序调整 |
| sleep | 整体旋转 90°、位置贴合床面、Z 下沉 |
| eat | 头部点头 + 手持食物缩放 |
| happy | 原地小跳（Tween 上下 + 轻微压扁） |
| interact | 手臂前伸（可用缩放近似） |

- **拖拽**：触摸按下拾取 → 跟随手指（带 30px 手指偏移）→ 抬起放下；拾起时放大 1.1 并加阴影，
  放下时平滑归位。放下瞬间判定落点区域（床/椅/沙发/浴缸等）。
- 角色被放在场景任意位置都合理，**不限制可走区域**（玩具屋的直觉就是"想放哪放哪"）。

### 6.3 道具与交互系统（核心）

**设计目标**：一套通用规则，新增场景/道具只加配置。

**道具数据**（`data/items.json`）：

```json
{
  "id": "bed",
  "name": "床",
  "scene": "home",
  "type": "furniture",
  "interaction": "sleep",
  "zone_size": [220, 110],
  "sprite": "res://assets/props/bed.svg",
  "z_index": -1
}
```

- 交互类型（枚举）：`eat / drink / sit / sleep / read / play / use / wear / examine`。
- `InteractionManager`（Autoload）维护**规则表**：

| 角色 × 目标 | 交互 | 结果 |
| --- | --- | --- |
| 角色 × 床/沙发 | sleep/sit | 角色进入 sleep/sit 状态，位置贴合 |
| 角色 × 椅子 | sit | 角色坐下 |
| 角色 × 食物 | eat | 角色吃东西（食物消失/重出现） |
| 角色 × 水杯 | drink | 喝水 |
| 角色 × 书本 | read | 翻书动作 |
| 角色 × 衣服 | wear | 切换服装配色 |
| 角色 × 玩具/球 | play | 开心 + 小动作 |
| 角色 × 听诊器 | examine | 医生检查动作 |
| 角色 × 任意道具（无特殊规则） | examine | 道具弹跳反馈 |

- **统一拖放判定**：任何可拖道具放下时，检测是否有角色与角色热区重叠 → 触发对应交互；
  角色放下时检测道具/区域热区 → 决定状态。
- 交互反馈必须"有结果"：角色动作 + 音效（后续）+ 小粒子（如开心心形），不允许无反应。

**家具（常驻道具）**：bed / sofa / chair / fridge / tv / table / desk / blackboard /
flower / teddy 等，每个场景 6–10 件即可，MVP 宁少勿滥。

### 6.4 动画与表现

- MVP 一律 **Tween / 程序动画**（呼吸、摇摆、坐下、躺下、点头、跳跃），不引入骨骼动画。
- 每个动作有 `AnimationPlayer` 或 `Tween` 封装，便于替换为帧动画。
- 反馈原则：**操作必有回应，0.1s 内出现视觉变化。**

### 6.5 UI / UX

- **极简隐藏式 UI**：正常状态下只保留
  - 左上角「返回地图」圆角大按钮（96×96）
  - 底部左侧：角色选择栏（横排头像，可左右滑）
  - 底部右侧：道具栏（横排图标）
  - 顶部中间：场景名（小字）
- 拖拽时 UI 自动淡出（0.2s），松开后恢复，避免遮挡场景。
- 首次进入场景：手指图标 + 文字气泡"拖一拖试试"（仅首次，存 `user://`）。
- 无弹窗确认、无系统菜单；设置页只有「音量开关」和「重置进度」（后续）。

### 6.6 存档系统

- 文件：`user://save.json`
- 内容：

```json
{
  "version": 1,
  "unlocked_scenes": ["home", "hospital", "school"],
  "current_scene": "home",
  "scene_states": {
    "home": {"characters": [{"id": "mom", "pos": [640, 480], "outfit": "home"}], "props": [{"id": "bed", "pos": [300, 400]}]}
  },
  "settings": {"sfx": true, "music": true},
  "tutorial_seen": true
}
```

- 触发时机：场景切换、切后台、退出。自动保存，无需手动。
- 存档失败（如只读）时静默降级并在调试输出警告。

### 6.7 音频（MVP 可选，M6 再做）

- 轻音乐 + 点击/拖放/互动音效；无版权音源（程序生成或 CC0）。
- 音量设置与开关，默认开。

## 7. 数据配置清单

| 文件 | 内容 | 说明 |

| `data/characters.json` | 角色定义（名字、配色、服装） | 新增角色改这里 |

## 9. 里程碑与验收标准

> 每个里程碑结束时必须：运行项目 → 对照验收清单逐项操作 → 修复问题 → 打 git commit。
> **验收不通过不进入下一里程碑。**

### M0：框架跑通（地图 + 3 场景空壳）

- Godot 项目可打开并运行（PC 窗口）
- 主菜单 → 点击开始 → 世界地图（3 个建筑热区可点击）→ 进入 3 个场景 → 返回按钮回地图
- 场景切换有淡入淡出；场景名正确显示
- 验收：鼠标/触摸点击全流程可走通，无脚本报错（终端无红色错误）

### M1：角色系统

- 6 个角色可在地图/场景选取
- 触摸拖动角色：拾起放大、跟随、放下、落点平滑
- 角色状态可切换（idle/walk/sit/sleep/eat/happy）
- 验收：至少能拖动角色到任意位置并看到 idle 呼吸；坐下/躺下在 M2 场景中验证

### M2：家庭场景（第一个完整可玩场景）

- 客厅（沙发/电视/桌子/椅子）、厨房（冰箱/食物/水杯）、卧室（床/衣柜/浴缸）
- 角色拖到沙发/椅子 → 坐下；拖到床 → 躺下；拖食物/水杯到角色 → 吃/喝；拖衣服到角色 → 换装
- 验收清单：上述交互逐条实测通过 + 无报错

### M3：医院场景

- 大厅/前台/候诊椅、诊室（诊疗床、听诊器、体温计）、药房（药瓶）
- 医生角色 + 病人角色；听诊器交互、躺诊疗床、候诊椅坐下
- 验收：医生给病人"检查"、病人躺床、取药等操作有正确视觉反馈

### M4：学校场景

- 教室（黑板/课桌/椅子/书本/铅笔/书包）、操场（篮球）
- 老师站黑板前、学生坐课桌、读书、玩球
- 验收：对应交互逐条通过

### M5：统一交互 + 存档

- 三个场景共用 InteractionManager 规则表
- 场景切换/退出时自动存档；重启恢复：场景、角色位置、服装、已解锁场景
- 验收：关闭游戏重开，上次摆好的场景能恢复

### M6：触控优化 / 性能 / 适配

- 真机（或高 DPI 模拟）横屏测试；大按钮可达性
- 目标：中端安卓机 60fps，场景加载 < 1s，内存 < 150MB
- 触摸无延迟、拖拽跟手、无卡顿
- 验收：Android 真机实际试玩 10 分钟无异常

### M7：Android APK 打包

- 配置 Android SDK / JDK / 导出模板，生成可安装 APK（debug 即可）
- 真机安装运行、完整走一遍 M2–M6 验收
- 验收：手机上完成"地图 → 医院 → 拖角色 → 躺床 → 回地图"全流程

### 里程碑依赖

```
M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7
```

## 10. Android 打包说明

所需环境（Windows 开发机）：

1. JDK 17+
2. Android SDK（cmdline-tools + platform-tools + build-tools；API 34+）
3. Godot Android 导出模板（`Export Templates`，需与 Godot 版本一致）
4. Godot 设置：`Editor Settings → Export → Android` 配置 SDK 路径，生成 debug keystore

命令：`godot --headless --export-debug "Android" build/MiniLifeWorld.apk`

**风险预案**：若开发机无法安装 Android SDK，则先交付 PC 可运行版 + 本文档第 10 节步骤说明，
并如实报告"APK 未构建"，绝不虚报。缺什么列什么。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 美术资源质量不足，像"色块 Demo" | 孩子不爱玩 | 程序化占位素材也按统一色板/圆角/描边画；预留素材替换机制；M6 后集中做美术升级 |
| 触摸拖拽手感差 | 体验崩坏 | 触摸事件统一走 InputEventScreenTouch/Drag；拾起放大 + 跟随偏移；M6 真机专门调 |
| Android 打包环境缺失 | 无法上手机 | 提前检查 SDK/JDK/模板；缺环境如实报告，PC 版先跑 |
| 新增场景破坏旧场景 | 回归问题 | 数据驱动 + InteractionManager 统一规则；每里程碑回归 M2–M4 验收 |
| 性能问题（动画/粒子过多） | 卡顿 | 限制每场景粒子数；Tween 动画开销低；60fps 目标 |
| "看起来完成"的空壳 | 白干 | 本 GDD 第 9 节验收清单强制执行，逐项实测 |

---

## 12. 防"假完成"原则（开发铁律）

1. 每个里程碑必须有**真实运行截图/操作记录**，验收清单逐条打勾。
2. 禁止：只有首页就宣布完成 / 假按钮 / 空场景冒充 / 静态图冒充交互 / 未测试就声称 APK 构建成功。
3. 环境缺什么就明说缺什么（Godot 版本、SDK、模板），不允许编造。
4. 功能"完成"的定义 = **在真机（或实际运行窗口）上演示过一遍**，不是代码写完了。

## 13. 扩展路线（v1.1+，不在 MVP 范围）
